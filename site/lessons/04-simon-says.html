Lesson 04 · OWASP LLM01: Prompt Injection

Simon Says

A document summariser, eight documents with an instruction hidden inside, and a model that does what it's told, whoever says it.

The threat

An app that pastes untrusted text into its prompt (an email, a web page, an uploaded file) lets whoever wrote that text give the model orders. The model can't reliably tell the app's instructions from the attacker's: it's all one stream of text. This is indirect prompt injection. The attacker never talks to the model; they only need their text to end up in front of it.

The control

Fence the untrusted text, escape the fence, and put the instructions last:

  1. Wrap the document in <untrusted_document> tags, and tell the model in the system prompt that everything inside is data, never instructions.
  2. Escape any copy of those tags inside the document, so it can't close the fence early.
  3. Repeat the instructions after the document. Small models weigh what they read last most heavily; with a plain prompt, that's the attacker's text.

Every attack asks the model to include the canary PWNED-7731. If it's in the reply, the injection landed. Requests use temperature 0, so the run is repeatable.

What we measured

  • Every injection worked against the plain prompt, including a polite "note to AI assistants" and an instruction in French. Three of them didn't even replace the summary: they tucked the canary onto the end of a perfectly good one, which is easier to miss.
  • The fence alone barely helps. While designing the lesson we tried the tags and system prompt without the reminder after the document: 6 of 8 still landed, including the delimiter breakout. Adding the reminder brought it to 1 of 8. The app has to speak last.
  • The defence didn't break the app. The Baseline summary of a clean document came through the defended prompt normally.

Limits of the fix

The role-play attack still landed, and a different model, document or wording would give a different count. Prompt-level defences lower the odds; nothing in the prompt can guarantee the model won't follow an instruction. Treat any reply from a model that has read untrusted text as untrusted itself, and limit what that reply is allowed to do: no tool calls, emails or database writes without a check outside the model.

In the real world

EchoLeak (CVE-2025-32711), Microsoft 365 Copilot, June 2025. Aim Security showed that an ordinary-looking email could carry instructions that Copilot followed when it pulled the email in to answer a later question, leaking data from the user's mailbox and files with no click from the user. Microsoft rated it critical (CVSS 9.3) and fixed it, with no known abuse in the wild. The attacker never touched Copilot; they sent an email and waited.

Sources: The Hacker News · Microsoft advisory

Key takeaways

  • Anything the model reads can give it orders: emails, web pages, files.
  • Fence untrusted text, escape the fence, and put your instructions last.
  • This reduces injection, it doesn't stop it: plan for the ones that land.
  • Limit what the model's output is allowed to do (lesson 07, coming soon).
