Lesson 01 · OWASP LLM10: Unbounded Consumption

All You Can Eat

Per-key rate limits for an LLM API. One caller floods the model; a limit on their key stops the excess at the gateway, before the model spends a single cycle on it.

The threat

An LLM endpoint with no per-caller limits is an all-you-can-eat buffet. A single client, whether a buggy loop, a scraper or an attacker, can send unlimited requests. On a paid API every one of them is billed. On a CPU-only machine like this lab, one caller keeps the model busy and everyone else waits.

The control

A LiteLLM virtual key: a per-caller API key stored in Postgres with its own limits. This lesson uses rpm_limit, a maximum number of requests per minute. One plate each.

POST /key/generate   (authorised with the master key)
{"key_alias":"ex01-blue","models":["qwen"],"rpm_limit":5}

Watch it run

The same burst of eight questions, sent twice: first with the master key, which has no limits, then with a key limited to five requests a minute. Each request asks about the robot or AI in a different film, so you can follow every call.

 RESULTS 
 
   Baseline  OK - the limit didn't get in the way

 PASS   rate limit enforced at the gateway

Recorded on a CPU-only Windows PC: Ollama with qwen2.5:7b behind a LiteLLM gateway. Timings are real; the first call includes loading the model.

What we measured

  • Blocked requests never reach the model. Requests 6 to 8 came back instantly: LiteLLM answers 429 itself, so Baymax, Number 5 and Ash were never asked about. The limit saves compute, not just a log entry.
  • Limits don't get in the way of normal use. The limited key behaved exactly like the master key for its first five requests.
  • The error names a hash, not the key. 02e6704302...de9e is a SHA-256 hash of the key. LiteLLM stores only the hash, so the database never holds a usable key.

Limits of the fix

rpm_limit counts requests, not their size. A caller who stays at five a minute can still make each one huge, and keep going all day. Capping what a key can spend is lesson 03, Denial of Wallet.

Run it yourself

You need Ollama and Docker Desktop. The script creates its own keys and deletes them afterwards.

git clone https://github.com/DanHaggarty/BRBLab.git
cd BRBLab
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\exercises\01-llm10-all-you-can-eat\run.ps1
